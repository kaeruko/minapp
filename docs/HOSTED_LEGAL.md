# Hosted Terms / Privacy consent

Hosted BtoC registration uses versioned legal documents and records explicit acceptance on the server.

## Source of truth

The current document text and version identifiers live in:

```text
backend/src/hosted_legal.py
```

Current versions:

```text
Terms:   hosted-terms-2026-08-28
Privacy: hosted-privacy-2026-08-28
```

Do not silently edit the body while keeping the same version. Any substantive legal-text change must receive a new version identifier.

## Public legal endpoint

```http
GET /hosted/legal
```

The response contains:

- effective date
- support email
- current Terms version/title/body
- current Privacy version/title/body

Clients must fetch this endpoint before presenting Hosted registration.

## Registration contract

`POST /hosted/register` requires all six fields:

```json
{
  "login_id": "example-user",
  "password": "...",
  "terms_version": "hosted-terms-2026-08-28",
  "privacy_version": "hosted-privacy-2026-08-28",
  "terms_accepted": true,
  "privacy_accepted": true
}
```

Registration fails closed when:

- either acceptance flag is false or missing
- either version is missing
- a submitted version is not the current version
- unknown fields are present

Stale versions return a conflict response so the client can refetch `/hosted/legal` and ask the user to review the updated document.

## Audit record

Successful registration stores the following on both the Hosted `USER#... / PROFILE` and `AUTH#... / PROFILE` records:

```text
terms_version
privacy_version
terms_accepted = true
privacy_accepted = true
terms_accepted_at
privacy_accepted_at
```

The acceptance timestamp is generated by the server in UTC. The client does not supply the timestamp.

Recovery-code rotation preserves these fields because it replaces profiles from their current records rather than rebuilding them from a smaller schema.

## Existing accounts

Accounts created before this feature do not have a fabricated consent record. Do not backfill `accepted=true` for them without an actual user action. When Hosted gains its end-user registration/login UI, legacy accounts that require continued BtoC access should be handled through an explicit re-consent flow.

## UGC and privacy scope

The Hosted Terms include a zero-tolerance rule for objectionable content and abusive behavior and identify the safety contact. The Hosted Privacy Policy reflects the current implementation, including:

- login/internal/auth identifiers
- hashed recovery credentials
- group/app/runtime data
- user-provided content
- legal-consent versions/timestamps
- hashed abuse-control keys
- AWS infrastructure processing
- account deletion behavior

The documents deliberately do not claim that Hosted already has an in-app reporting/blocking UI. That UI remains a separate product requirement before a public UGC rollout.
