# アプリのキャッシュとセーブデータ

キャッシュは再取得できる表示用データ、セーブはユーザーの操作で生まれる永続データとして扱う。
WebView の作り直し、別作品の起動、公開バージョンの更新をセーブ削除の契機にしない。

## 保存先と分離単位

| 対象 | 保存先・分離単位 | 寿命と消去 |
| --- | --- | --- |
| ホーム／カタログのビルトイン HTML | Flutter 同梱 asset | ホストアプリの更新で置き換える。起動時の WebView 全体のキャッシュ削除は不要 |
| ビルトインのメモ・育成セーブ | SharedPreferences の `builtin_state_v1::<appId>::<key>` | WebView の再生成、ユーザーアプリ起動、ログアウト、教室変更で消去しない |
| Hosted の共有データ | Runtime の `minapp.state` | サーバーが認可したグループ・アプリ単位。公開バージョンや一時的な Runtime token に依存しない |
| Hosted の個人データ | Runtime の `minapp.userState` | 上記に認証ユーザーを加えた単位。子 HTML にユーザー ID を選ばせない |
| Hosted のプレビュー | 専用の Preview Runtime 名前空間 | 本番の共有・個人データと分離する |
| ユーザーアプリの Cookie／localStorage／WebView cache | WebView の共有データストア | ユーザーアプリを開く前と教室変更時に消去する。永続セーブ先として提供しない |
| Girls のアプリ一覧 | メモリ内 `GirlsAppsCache`、セッション・グループ単位 | 5 分の表示キャッシュ。再取得・権限確認が成功するまで起動などの操作を有効にしない |

ビルトインのセーブはログインを必要としない**この端末のデータ**。アカウントを切り替えても
同じものを使い、別端末との同期はしない。ホームのビルトインと、グループに配置した同名の
Hosted アプリは保存先も寿命も別で、自動コピーしない。
アプリのアンインストールや OS のアプリデータ消去後の復元は保証しない。

## WebView の全消去を単純にやめない理由

ユーザーアプリは同じオリジンの異なる capability URL 配下で動く。
URL のパスと navigation 制限だけでは Cookie／localStorage を作品別に隔離できない。
また `clearLocalStorage()` は現在のページだけを消す操作ではなく、共有 WebView データストアに
影響する。そのためユーザーアプリの起動前消去は維持し、公式アプリの永続データをその外に置く。

これはブラウザ保存 API すべての完全な sandbox を保証するものではない。
IndexedDB、Cache Storage、同時に開いた複数の WebView まで作品ごとに隔離する設計が必要に
なった場合は、専用オリジン／データストアを別途設計する。作品に永続 localStorage を提供する
目的で現在の起動前消去だけを外さない。

サーバーの認可付き作品レスポンスは既に `Cache-Control: no-store`。
今回はダウンロード ZIP の永続キャッシュや期限切れ capability のオフライン利用を追加しない。
専用教室の従来 `AppWebViewPage` は従来どおり永続ブラウザセーブを提供しない。
Hosted の保存 API は [Runtime bridge](HOSTED_RUNTIME_BRIDGE.md) に従う。

## ビルトインの読み書き

- native channel の登録完了後に HTML を読み込む。
- native に値があれば常にそれを採用する。値なしの場合だけ、読める旧 localStorage を検証して
  取り込む。移行の保存成功前に旧データを消さない。
- native の読込・保存エラー、不正な保存値を「値なし」と扱わない。別の保存先へ切り替えたり、
  新しい卵や空のメモで上書きしたりしない。
- メモの編集は初回読込後に有効にし、入力時の値を順番に保存する。保存成功応答前に
  「保存しました」と表示しない。育成の時間更新と操作による保存も重ねない。
- メモの入力はイベント中に native へ送る。WebView 内に未送信の保存待ち行列を作らず、
  直後に閉じても native が受け取った最新の入力まで処理する。
- native 側もページをまたぐ読み書きを直列化し、先に受け取った保存を再オープン時の読込が
  追い越さないようにする。読込前に Preferences を再取得し、失敗した書込が残した Dart の
  キャッシュを保存済みの値として返さない。PR #271 と同じ保存キーとバックエンドを維持する。
- 保存エラー時は画面に失敗を表示し、入力中のメモを残し、自動更新・新たな保存要求を止める。
  すでに native が受け取った要求は処理を完了するが、その応答でエラー表示を消さない。

以前の WebView 消去ですでに失われた localStorage は復元できない。旧データが見つからず
native にも保存がない場合だけ初期状態を作る。単独で HTML を開く場合の localStorage は
そのブラウザの保存領域であり、モバイルの native セーブとは別扱いになる。

## 検証

- Flutter の WebView fake を使い、channel 登録完了前に読み込まないこと、再オープン時の復元、
  アプリ ID の分離、ブラウザデータ消去が native セーブに影響しないことを確認する。
- HTML の JavaScript を実行し、旧データ移行、native 優先、失敗時の停止、非同期保存中の入力・
  時間更新を確認する。
- Android／iOS 実機では「メモ入力・育成 → 閉じる → 別ユーザーアプリ起動 → 再オープン →
  ホスト再起動」の順で確認する。fake テストだけでは OS の終了時のディスク書込や復元を保証しない。
