# Phase 6A: central classroom Directory

Phase 6A implements the operator-owned routing-only Directory described in `PHASE6_FEDERATED_CLASSROOMS.md`.

The Directory answers only two public questions:

- `POST /v1/classrooms/resolve`: resolve a classroom join code to a tenant descriptor
- `GET /v1/tenants/{tenant_id}`: refresh a configured tenant descriptor

It does not store student/teacher passwords, Cognito tokens, AWS credentials, child ZIPs, or runtime application data. Classroom codes select a tenant; they are not authentication credentials.

## Security properties

- the public Lambda has read access to tenant/code records and update access only for its rate-limit counters
- there is no public admin mutation route
- tenant lifecycle changes are performed with the operator CLI and the operator's AWS credentials
- classroom codes are generated by the CLI, normalized, SHA-256 hashed, and only the hash is stored
- raw classroom codes are not written to application/audit logs
- rotated classroom codes stop resolving immediately; already configured clients continue refreshing by immutable `tenant_id`
- only `https` tenant origins are accepted; userinfo, query, fragment, non-default ports, paths, IP literals, localhost/local-only names, and malformed hosts are rejected
- a tenant cannot be activated until its `/tenant-info` endpoint is reachable and reports the same immutable `tenant_id` and API protocol
- unknown tenant schema/protocol versions fail explicitly; there is no fuzzy classroom lookup or fallback
- public requests are rate-limited by a SHA-256 hash of source IP in a short-lived DynamoDB TTL record; API access logs do not include request bodies or classroom codes

## Directory data model

The DynamoDB table uses `PK` / `SK` keys.

Tenant record:

```text
PK = TENANT#{tenant_id}
SK = META
entity = tenant
schema_version = 1
tenant_id
display_name
status = pending | active | inactive
api_base_url                 # after endpoint registration
api_protocol_version = 1
config_revision
current_code_hash
created_at
updated_at
```

Classroom code mapping:

```text
PK = CODE#{sha256(normalized_code)}
SK = META
entity = classroom_code
code_hash
tenant_id
status = active | rotated
created_at
rotated_at?                  # rotated record only
```

Audit records contain tenant/config lifecycle metadata only:

```text
PK = AUDIT#{tenant_id}
SK = {timestamp}#{random suffix}
entity = audit
tenant_id
action
created_at
```

Rate-limit records use `RATE#...` keys and DynamoDB TTL. They contain only a hash of the request source and counters.

## Deploy the operator-owned Directory stack

This is a separate Terraform state from every tenant stack.

```powershell
Copy-Item infra\directory\terraform.tfvars.example infra\directory\terraform.tfvars
Copy-Item infra\directory\backend.hcl.example infra\directory\backend.hcl
```

Set `operator_account_id` to the AWS account that owns the central MinApp Directory. Terraform has a fail-fast account guard and refuses to deploy the stack through credentials for a different account.

Bootstrap an S3 remote-state bucket in that operator account, with versioning, encryption, public access blocking, and a dedicated Directory state key. Then initialize:

```powershell
terraform -chdir="infra/directory" init -backend-config="backend.hcl"
terraform -chdir="infra/directory" plan -out="tfplan"
terraform -chdir="infra/directory" apply "tfplan"
```

Get the two operator values used below:

```powershell
$directoryApi = terraform -chdir="infra/directory" output -raw directory_api_base_url
$directoryTable = terraform -chdir="infra/directory" output -raw directory_table_name
```

## Operator CLI

The CLI deliberately uses the operator's current AWS credentials directly against DynamoDB. Do not expose it as a public web endpoint.

Examples below assume an AWS profile called `minapp-operator`.

### 1. Create a pending tenant

```powershell
python tools/minapp_directory.py `
  --table-name $directoryTable `
  --profile minapp-operator `
  --region us-west-2 `
  tenant create `
  --display-name "Example Programming School"
```

The command prints a new immutable `tenant_id` and a classroom code. The raw classroom code is shown for delivery but is not stored. If it is lost, rotate it instead of trying to recover it.

### 2. Deploy the tenant AWS stack

Use the returned `tenant_id` as that tenant's immutable Phase 6B Terraform input. Deploy into the customer-owned AWS account and obtain its `api_base_url`.

### 3. Register the endpoint

```powershell
python tools/minapp_directory.py `
  --table-name $directoryTable `
  --profile minapp-operator `
  --region us-west-2 `
  tenant update-endpoint `
  --tenant-id <tenant_id> `
  --api-base-url <tenant_api_base_url>
```

`update-endpoint` validates the URL and calls `<tenant_api_base_url>/tenant-info`. A mismatched tenant ID, protocol, service, or response schema aborts the change.

Endpoint changes increment `config_revision`.

### 4. Activate

```powershell
python tools/minapp_directory.py `
  --table-name $directoryTable `
  --profile minapp-operator `
  --region us-west-2 `
  tenant activate `
  --tenant-id <tenant_id>
```

Activation verifies `/tenant-info` again. Only `active` tenants are returned by the public API. `pending` tenants fail closed as not found; `inactive` tenants return a typed `410 classroom_inactive` response.

### 5. Rotate a classroom code

```powershell
python tools/minapp_directory.py `
  --table-name $directoryTable `
  --profile minapp-operator `
  --region us-west-2 `
  tenant rotate-code `
  --tenant-id <tenant_id>
```

The old hash is marked `rotated`, a new code hash becomes active, and the raw new code is printed once. Existing devices continue using `GET /v1/tenants/{tenant_id}` and are unaffected.

### 6. Deactivate

```powershell
python tools/minapp_directory.py `
  --table-name $directoryTable `
  --profile minapp-operator `
  --region us-west-2 `
  tenant deactivate `
  --tenant-id <tenant_id>
```

## Public API

Resolve:

```http
POST /v1/classrooms/resolve
Content-Type: application/json

{"code":"7K2M-4Q9P-W6TX"}
```

Successful response:

```json
{
  "schema_version": 1,
  "tenant_id": "2d8860f2b45b4eaa9b8f97b935f55f50",
  "display_name": "Example Programming School",
  "api_base_url": "https://example.execute-api.us-west-2.amazonaws.com",
  "api_protocol_version": 1,
  "config_revision": 2,
  "valid_for_seconds": 86400
}
```

Configured-client refresh:

```http
GET /v1/tenants/2d8860f2b45b4eaa9b8f97b935f55f50
```

Typed errors include:

```text
400 invalid_request
400 invalid_classroom_code
404 classroom_not_found
410 classroom_inactive
409 incompatible_tenant_config
429 rate_limited
503 directory_unavailable
```

Requests with unknown JSON fields are rejected. The service does not guess malformed classroom codes, redirect to arbitrary tenant URLs, or fall back to another tenant.
